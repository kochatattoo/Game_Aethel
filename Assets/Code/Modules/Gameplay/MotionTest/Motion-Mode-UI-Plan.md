# Motion: переключение режимов через runtime-HUD

Дата: 03.11.2026.  
Область: только `Test_MotionScene` и MotionTest-полигон.  
Статус: этап реализован и проверен в Unity Editor 03.11.2026.

Актуальное развитие правил ОД и мирового времени: `Motion-World-Turn-Plan.md`. Описание ручного завершения при нулевых ОД ниже относится к первому этапу; затем оно заменено автоматическим завершением.

Глобальные планы A1–A13 и документы Obsidian в эту задачу не входят.

## Цель

Во время Play пользователь может без EditorWindow:

- увидеть текущий режим: обычное движение или тактика;
- войти в тактический режим кнопкой на HUD;
- видеть остаток и максимум ОД;
- при нулевых ОД завершить тестовый ход и восстановить бюджет;
- выйти из тактики и вернуться к обычному движению.

Правила стоимости клеток и бюджет ОД не меняются. Отряд, противники, настоящий `Encounter`, сохранения и продуктовая кампания не входят в задачу.

## Реализованное поведение

- `MotionTestHud` создаёт Screen Space Overlay Canvas при запуске Play.
- Индикатор показывает `Обычное движение`, `Вход в тактический режим…` или `Тактический режим`.
- Кнопка `Войти в тактику / Выйти из тактики` вызывает существующий `MotionTestController.SetCombat`.
- Кнопка `Завершить ход — обновить ОД` вызывает существующий `NewTurn`.
- При нулевых ОД перемещение отклоняется без изменения позиции, бюджета и ревизии; остаётся завершение хода.
- Во время выравнивания и тактического маршрута кнопка завершения хода недоступна.
- Выход во время тактического маршрута ожидает его завершения, затем включает обычный NavMesh-режим.
- Клики по HUD не отправляют команды движения и не управляют камерой.
- EditorWindow сохранён как отладочный инструмент, но для переключения больше не требуется.

## Файлы

- `MotionTestHud.cs` — runtime Canvas, индикаторы и кнопки.
- `MotionTestController.cs` — создание HUD, доступность переключения, блокировка world input над UI.
- `MotionCameraController.cs` — блокировка camera input над UI.
- `../../../Editor/MotionTest/MotionRuntimeChecks.cs` — проверка настоящих UI-кликов через Input System.

## Проверка

Ручной сценарий:

1. Открыть `Test_MotionScene`, нажать Play и сфокусировать Game View.
2. Нажать `Войти в тактику` на HUD, дождаться выравнивания.
3. Перемещаться по клеткам до нулевых ОД.
4. Убедиться, что перемещение отклоняется, нажать `Завершить ход — обновить ОД`.
5. Нажать `Выйти из тактики` и продолжить обычное движение.

Автоматическая проверка: `Tools → PetProject → Motion → Run Runtime Checks`.

Результаты 03.11.2026:

## Решения автора — 03.11.2026

- **Q01 — принято текущее поведение.** При выходе герой остаётся в текущей позиции и возвращается к обычному NavMesh-движению. Восстановление позиции до входа не требуется.
- **Q02 — автоматическое завершение реализовано.** Ручная кнопка доступна при наличии ОД и отсутствии исполняемого маршрута. После полной траты ОД ход завершается автоматически; при нулевых ОД ручная кнопка недоступна.
- **Q03 — сохранение остатка ОД реализовано.** Повторный вход не восстанавливает бюджет бесплатно. Восстановление происходит на общей границе мирового цикла из `Motion-World-Turn-Plan.md`.
- **Q04 — свободное переключение остаётся.** Ручной вход в пошаговый режим и выход из него планируется не только для полигона, но и как игровая возможность.
- **Q05 — технический HUD остаётся.** Отдельный prefab и художественное оформление сейчас не требуются.
