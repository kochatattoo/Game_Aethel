# Motion: мировой шестисекундный ход и сохранение ОД

Дата: 03.11.2026.  
Область: сначала только `Test_MotionScene`; архитектурная граница должна позволять позднее подключить NPC и настоящий `Encounter`.  
Статус: согласовано, реализовано и проверено в Unity Editor 03.11.2026.

Связанная завершённая задача: `Motion-Mode-UI-Plan.md`. Глобальные планы A1–A13 и Obsidian не изменяются.

## Задуманное правило

В обычном режиме мир движется по общим циклам длительностью **6 секунд**. Цикл представляет игровой ход, за который сущность может выполнить действия, измеряемые ОД. Для всех сущностей используется общий мировой контекст, а не независимые Unity-таймеры на каждом объекте.

При входе в пошаговый режим мировое время останавливается. Игрок может свободно войти в тактику и выйти из неё. Повторный вход сам по себе не восстанавливает ОД: остаток сохраняется до разрешённого мирового восстановления.

Это авторский гибрид по мотивам real-time/with-pause и пошагового режима BG3/Pathfinder, а не утверждение о буквальном копировании их внутренней реализации.

## Принятые правила

- Бюджет и стоимость текущего клеточного движения не меняются.
- В обычном режиме текущее свободное перемещение по NavMesh ОД не расходует.
- При первом входе доступен полный бюджет.
- При выходе из тактики текущий остаток ОД сохраняется.
- При повторном входе используется сохранённый остаток, если мировое восстановление ещё не произошло.
- Герой остаётся в текущей позиции при выходе; позиция до входа не восстанавливается.
- Ручное завершение хода доступно только при наличии ОД и отсутствии исполняемого маршрута.
- Ручное завершение отбрасывает оставшиеся ОД текущего тестового хода и начинает новый ход с полным бюджетом.
- При полной трате ОД тестовый ход завершается автоматически и начинается новый с полным бюджетом.
- При нулевых ОД ручная кнопка недоступна.
- Свободное переключение режимов остаётся не только в полигоне, но и в будущей игре.
- Текущий технический вид HUD сохраняется.

## Предлагаемая модель времени

### В обычном режиме

Один общий `WorldTurnClock` получает `deltaTime` от Unity-адаптера. Через каждые 6 секунд увеличивается номер мирового хода и публикуется событие нового цикла. Контексты NPC и игрока читают один источник времени.

Не создавать `Update`, корутину или `Invoke` отдельно для каждой сущности. Состояние ОД может храниться по `ActorId`, но часы должны быть общими.

### В тактическом режиме

Мировой clock останавливается. В одиночном Motion-полигоне ручное или автоматическое завершение вызывает новый тестовый ход и полный бюджет.

В будущем настоящем бою `Encounter` становится владельцем очереди и ОД. Мировой clock не должен параллельно менять бюджет во время пошагового столкновения.

### При входе в будущий бой

Начальные ОД участников формируются из сохранённого мирового состояния. После начала столкновения их изменением управляет только `Encounter`. При завершении боя остаток может быть записан обратно в мировое состояние по отдельному согласованному правилу.

## Пример целевого сценария

1. Мировой ход начался, у героя 6/6 ОД.
2. Игрок вошёл в тактику и потратил 2 ОД.
3. Игрок вышел, не завершая ход: сохранено 4/6 ОД.
4. До мирового восстановления игрок снова вошёл в тактику: доступно 4/6 ОД.
5. Игрок вышел. После разрешённого мирового восстановления бюджет снова становится 6/6 ОД.
6. Если в тактике потрачены все ОД, начинается новый тестовый ход с 6/6 ОД без ожидания мирового таймера.

## Согласованные решения — 03.11.2026

- **W01 — общая граница мирового хода.** Все сущности восстанавливаются одновременно на ближайшей шестисекундной границе. Если выйти из тактики за 0,2 секунды до границы, ОД восстановятся через 0,2 секунды. Это принятое свойство общей раундовой модели.
- **W02 — clock останавливается во всех пошаговых состояниях.** Сюда входят выравнивание, тактический ввод и исполнение маршрута. В меню с `Time.timeScale = 0` clock также не продвигается.
- **W03 — диагностика на HUD включена.** В обычном режиме показываются сохранённые ОД и время до общей границы: `ОД для тактики: 4/6 · новый мировой ход: 2,4 c`.
- **W04 — текущий объём хранит состояние только в памяти Play.** Сериализация номера мирового хода, оставшегося времени и бюджетов относится к будущему сохранению кампании.

## Реализация

### Этап 1. Чистые правила и тесты

Добавить независимый от Unity clock и состояние остатка ОД. Проверить:

- отсутствие восстановления до разрешённой границы;
- восстановление на границе;
- сохранение остатка при повторном входе;
- отсутствие продвижения в тактике и паузе;
- корректный перенос остатка `deltaTime` без накопления ошибки;
- большой `deltaTime`, покрывающий несколько циклов;
- ручное и автоматическое завершение тестового хода.

### Этап 2. Подключение к MotionTest

- Controller продвигает clock только в разрешённых состояниях.
- Новая тактическая сессия получает сохранённый остаток вместо безусловного полного бюджета.
- При выходе остаток записывается обратно.
- Позиция и текущие правила движения не меняются.

### Этап 3. HUD и автоматическое завершение

- Показать мировой остаток и обратный отсчёт в обычном режиме.
- Скрывать/блокировать ручное завершение при нулевых ОД.
- Автоматически начинать новый тестовый ход после полной траты ОД и завершения принятого действия.
- Не запускать автоматический новый ход посреди исполняемой анимации маршрута.

### Этап 4. Проверка через Unity MCP

- Native Unity Test Runner для правил clock и существующих Tactics-тестов.
- Runtime Checks: потратить часть ОД → выйти → войти до восстановления → проверить остаток → дождаться/имитировать границу → проверить восстановление.
- Проверить ручное завершение, автозавершение, выход во время маршрута и отсутствие world/camera input по HUD.
- Повторить Motion Editor Checks и проверить Console.
