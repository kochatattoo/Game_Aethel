# Motion + Enemy_Skeleton: план первого тестового боя

Дата: 03.11.2026.  
Область: `Test_MotionScene`, один герой и один `Enemy_Skeleton`.  
Статус: реализовано и проверено в Unity Editor 04.11.2026. Тестовая сцена сохранена и готова к ручной проверке в Play Mode.

Связанные этапы: `Motion-Mode-UI-Plan.md`, `Motion-World-Turn-Plan.md`. Глобальные планы A1–A13 и Obsidian не изменяются.

## Целевой пользовательский сценарий

1. Игрок видит скелета в обычном режиме.
2. Клик по скелету задаёт цель; герой следует к нему через NavMesh без real-time атаки.
3. Скелет замечает героя через существующий принцип vision/FOV/LOS.
4. Мировой шестисекундный clock останавливается; свободные real-time действия обеих сторон блокируются.
5. Герой и скелет занимают разные допустимые клетки, создаётся настоящий `Encounter` с инициативой, HP, ОД и очередью.
6. В ход героя игрок перемещается по сетке, атакует соседнего скелета или завершает ход.
7. В ход скелета простой AI приближается по допустимому пути, атакует при соседстве и завершает ход.
8. Победа показывает смерть скелета и возвращает героя к обычному движению. Поражение показывает отдельное состояние без возврата к обычному управлению.

Добровольный тактический режим без противника сохраняется. Обнаружение скелета переводит его в настоящий бой, а не создаёт второй параллельный режим.

`EnemyFactory` сейчас требует полного `HeroFacade`, связывает старые health/attack/loot/VFX и создаёт real-time противника. Для Motion-полигона не следует запускать весь этот путь. Нужна отдельная тестовая оболочка с сохранением визуального prefab и Animator.

## Ключевое архитектурное правило

`Encounter` — единственный владелец HP, клеток, занятости, ОД, очереди и RNG во время боя. `MotionTestSession` продолжает обслуживать только добровольное одиночное перемещение и не получает HP, атаку или AI.

Unity-компоненты:

- предоставляют начальные позиции и параметры;
- отправляют команды игрока/AI;
- проигрывают принятые события;
- не наносят урон и не списывают ОД самостоятельно.

## Предлагаемые компоненты

Названия ниже — предлагаемые, а не существующие API.

### `MotionEnemyTarget`

Маркер скелета на сцене: стабильный `ActorId`, фракция, ссылки на корень, Animator, agent и detection. Клик в обычном режиме выбирает этот объект как цель подхода.

### `SkeletonCombatDirector`

Координатор одного тестового столкновения:

```text
Exploration → FollowingSkeleton → Detected → Aligning
Aligning → HeroTurn / EnemyTurn
HeroTurn / EnemyTurn → ResolvingPresentation → HeroTurn / EnemyTurn
Любой активный бой → Victory / Defeat
Victory → Exploration
Defeat → Reset
```

Он владеет жизненным циклом боя, создаёт `Encounter`, связывает ActorId с представлениями и не даёт AI отправить следующую команду до завершения текущего представления.

### `EncounterActorView`

Unity-адаптер героя/скелета:

- получает события Moved/AttackHit/AttackMiss/ActorDefeated;
- проигрывает заранее рассчитанный маршрут или соответствующую анимацию;
- отображает snapshot;
- не содержит собственного HP/ОД;
- отключает конкурирующие real-time компоненты на входе и восстанавливает только разрешённые на победном выходе.

### `SkeletonDetectionAdapter`

Использует существующий `VisionSensor`/настройки скелета и выдаёт событие обнаружения director. Не включает `AgentMoveToHero`, не атакует и не меняет HP. Существующий основной gameplay-путь при этом не переписывается.

### `MeleeEncounterAgent`

Простой AI без доступа к Unity Transform:

1. Если цель соседняя и хватает ОД — предложить Attack.
2. Иначе найти допустимую соседнюю с героем клетку с минимальной стоимостью пути с учётом занятости.
3. Если путь доступен — предложить Move; после представления заново прочитать snapshot.
4. Если атака/движение невозможны или ОД закончились — предложить EndTurn.

AI не должен знать скрытое положение героя вне правил обнаружения. Для первого боя после начала Encounter цель считается известной.

### Расширение HUD

Сохранить текущий технический HUD и добавить только необходимое:

- HP героя и скелета;
- чей ход и номер раунда;
- ОД активного участника;
- выбранная цель, результат d20, урон/промах;
- кнопка End Turn только в допустимом ходе героя при наличии ОД;
- Victory/Defeat и Reset после завершения.

В обычном режиме сохраняются мировые ОД и обратный отсчёт.

## Начальные ОД и связь с мировым циклом

При создании боя герой переносит текущий мировой остаток ОД. Скелет получает свой мировой остаток либо полный бюджет, если записи ещё нет.

Сейчас `InitiativeOrder.BeginTurn` всегда выдаёт полный бюджет, поэтому потребуется явная поддержка начальных ОД в `Encounter`. Нельзя имитировать перенос скрытым изменением snapshot.

Во время боя мировой clock остановлен. После победы текущий остаток героя предлагается записать обратно в `WorldActionBudgets`; дальше применяется уже согласованная общая шестисекундная граница.

Для первого теста предлагается `EncounterRules`: 6 ОД, атака 1 ОД, текущий `MaxHeightStep` Motion-конфига. Это сохраняет правила полигона, а не использует прежний D1-бюджет 3 молча.

## Решения автора — 03.11.2026

- **C-Q01 — выход из настоящего боя только через победу или поражение.** Добровольная тактика без противника по-прежнему переключается свободно. Промежуточный выход с сохранением Encounter не реализуется.
- **C-Q02 — клик по скелету в ход героя означает Attack только по соседству.** При неверной дистанции отказ не тратит ОД. Автоматического подхода с атакой в тактике нет.
- **C-Q03 — технические параметры подтверждены.** Герой: 12 HP/4 damage; скелет: 5 HP/5 damage; defense 12, attack +3, 6 ОД, атака 1 ОД. Старые 10 damage real-time конфига не переносятся.
- **C-Q04 — поражение показывает Defeat и Reset.** Ввод останавливается, возврата к обычному режиму с нулевым HP нет.
- **C-Q05 — рабочее допущение:** остаток ОД героя после победы записывается обратно в мир, чтобы победа не обновляла бюджет бесплатно. Это допущение можно пересмотреть перед C02.

## Не входит в первый бой

Отряд, несколько противников, лут, квесты, campaign saves, full DI bootstrap, реакции, критические правила 1/20, дальний бой, LOS атаки, укрытия, AoE, динамические препятствия и многоэтажная сетка. Они не должны скрыто расширять эту задачу.

## Доработка цикла и ИИ — 06.11.2026

- Клик по скелету в обычном режиме запускает подход; если герой оказался на соседней клетке без обнаружения, создаётся Encounter и первая атака героя становится первой командой боя.
- Для внезапной атаки герой начинает первым независимо от результата инициативы. Обычное обнаружение по-прежнему использует d20 + бонус инициативы.
- Начальные мировые ОД применяются к первому ходу каждого участника, затем ход начинается с полного боевого бюджета.
- Решения скелета выбираются BehaviourTree с ветками Attack → Move → EndTurn. Параметры вынесены в `MeleeTacticsAIConfig`, для него добавлен custom Editor.
- Runtime Checks дополнительно проверяют внезапную атаку из соседней клетки за спиной, первый ход героя и расход 1 ОД.

## Фикс выбора цели и урона — 06.11.2026

- Для клика по скелету используется отдельный capsule по высоте модели. Исходные collider и `BladeSensor` не участвуют ни в выборе, ни в уроне.
- Подход в обычном режиме ведёт на ближайшую достижимую свободную клетку, соседнюю со скелетом по стороне.
- Проверки используют настоящие Input System клики по экранной проекции selection-capsule: подход, внезапная атака и атака в ход героя.
- Тактический урон скелета — 2 HP. Формула атаки: `d20 + AttackBonus >= Defense`; при попадании HP цели уменьшается на `Damage` атакующего, физическое касание не требуется.
