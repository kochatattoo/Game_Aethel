# Этап 2: файловые сохранения и слоты

Хранилище подключено к существующим SaveLoadService, PlayerProgress, меню и загрузчику сцен. Настройки звука/управления остаются в PlayerPrefs.

## Пользовательский сценарий

- «Новая игра» открывает выбор одного из трёх слотов. Занятый слот требует подтверждения замены. До успешного создания героя и мира файл не меняется; отмена создания сохраняет старый профиль.
- «Продолжить» выбирает самый свежий совместимый слот при старте приложения. В запущенном мире эта кнопка возвращает в игру.
- «Сохранения» позволяет загрузить выбранный слот. Во время игры доступна ручная запись текущего героя в слот. Перезапись и удаление требуют отдельного подтверждения.
- Активный слот нельзя удалить, пока его мир запущен. Удалённые файлы перемещаются в подкаталог Deleted для ручного восстановления.

## Файлы и формат

Каталог: `Application.persistentDataPath/Saves`. Для каждого слота используются `slot-N.json`, `slot-N.json.bak` и временный `slot-N.json.tmp`.

Envelope версии 1 содержит slotId, устойчивый profileId (GUID), UTC-время, JSON данных и SHA-256 от заголовка и данных. Это проверка целостности, а не защита от намеренного редактирования.

Перед записью выполняются capture, сериализация и обратное чтение с валидацией. Временный файл записывается и сбрасывается через Flush(true); существующий основной файл заменяется File.Replace на том же томе, предыдущий становится backup. Ошибка не выдаётся за успешное сохранение. Повреждённый основной файл не заменяет хорошую резервную копию: при следующей записи он сохраняется отдельно с суффиксом replaced.

При чтении повреждённого основного файла используется валидный backup. Более новая неизвестная версия не подменяется молча старой копией. Автосохранение также не может затереть несовместимый слот без явной замены через меню. Чтение и запись ограничены 8 МБ.

Для небольших текущих профилей чтение и атомарная запись выполняются синхронно на главном потоке. Запросы имеют одного владельца; фоновой записи и многопроцессной блокировки пока нет. При увеличении объёма мира следует вынести файловый I/O из главного потока, оставив захват Unity-состояния на нём.

## Совместимость

Если файловых слотов ещё нет, валидный `PlayerPrefs[Progress]` импортируется в слот 1. Точная исходная строка сохраняется в `legacy-playerprefs.json`. Исходный ключ не изменяется и не удаляется. Копия также предотвращает повторный импорт после удаления всех ранее импортированных слотов.

Снимок разделён на ProfileProgress (атрибуты, здоровье, показатели, валюта и покупки), LevelProgress (levelId, позиция, добыча, очищенные спавнеры) и RunProgress (runId, статус, безопасный уровень, признак расчёта награды). DTO не содержат UnityEngine.Object, реактивных свойств и ссылок на runtime-модификаторы.

RunProgress подготовлен для следующих этапов: текущий игровой цикл ещё не создаёт забеги и записывает статус None. Для Active/Interrupted адаптер умеет восстанавливать безопасный уровень без объектов арены; создание забега и расчёт награды должны быть подключены вместе с порталами и волнами.

HasPosition сохраняется явно: Unity JsonUtility может превратить отсутствующую вложенную позицию в нулевые координаты. Сохранённая позиция героя проверяется через NavMesh.SamplePosition; непригодная позиция оставляет героя в стартовой точке уровня. Высота агента больше не прибавляется при каждом восстановлении.

## Проверка и ограничения

Команда `Tools > PetProject > Save Storage > Run Storage Checks` выполняет синхронные NUnit-методы с SetUp/TearDown и дополнительные проверки адаптера. Это позволяет не сохранять и не перезагружать уже изменённую сцену Bootstrap. Обычный Unity Test Runner также обнаруживает тестовую сборку.

Интеграционный сценарий использует отдельный тестовый PlayerPrefs-ключ и уникальный каталог `Library/SaveStorageMigration/Smoke/<session>`. Основные пользовательские файлы не используются для тестовых перезаписей и удаления. Отчёты: `Library/SaveStorageMigration/*.json`.

Проверено 28.10.2026:

- 14/14 проверок файлов: запись/чтение, checksum, backup, отсутствующий и повреждённый основной файл, неизвестная версия, запрет перезаписи автосохранением, ошибка временной записи, архивирование, ограничение размера, защита путей и неизменность legacy-копии.
- 4/4 проверки адаптера: отсутствие позиции, текущее HP, данные уровня/покупок, прерванный забег и отбраковка отрицательной валюты.
- PlayMode: импорт старого формата, точная копия исходного JSON, запись слота 2, восстановление после порчи файла, удаление слота 1 и повторный запуск без повторного импорта.
- Через кнопки View: отмена замены занятого слота и отмена создания не меняют файлы; создание героя в слоте 3 выдаёт новый profileId, сохраняет слот 2, создаёт героя на NavMesh с HP=50 и уроном=7.
- Слот 2 дополнительно загружен нажатием кнопки мышью после создания слота 3; фактические HP и урон сверены с окном атрибутов. Последний запрос ошибок Console вернул пустой список.

В изолированном PlayMode-тесте автообновление ассетов и перезагрузка сборок временно блокируются, чтобы фоновые операции Unity Version Control не разрушали DI-сессию. Блокировки снимаются обработчиком ExitingPlayMode, в том числе при ручной остановке теста. Обычный запуск приложения не затрагивается.

Player build и аварийное завершение ОС во время File.Replace не проверялись. Атомарность опирается на локальную файловую систему и поддержку File.Replace; при отсутствии этой поддержки операция завершается ошибкой, без неатомарной подмены.
