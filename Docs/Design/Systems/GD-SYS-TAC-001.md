# GD-SYS-TAC-001 — Ядро тактического столкновения

**Статус:** реализован и проверен технический прототип D1. Числа и упрощения не являются окончательно утверждённым балансом GDD.  
**Основание:** GDD §3.2; дорожная карта D1, будущие D2–D4.  
**Модуль:** `PetProject.Tactics`, `Assets/_project/CodeBase/Modules/Tactics/Runtime`. Сборка не имеет Unity Engine references.

## Назначение и границы

Encounter хранит авторитетное состояние одного столкновения. Представление, UI и будущий AI отправляют команды и читают результат. Кадры Unity, анимация, физика и VFX сами по себе не продвигают симуляцию.

Это базовое столкновение с ближней атакой. Покрытие всех правил D&D, классов, критических попаданий, дальнего боя и заклинаний относится к следующим этапам.

## Фактические типы

- `ActorDefinition`: неизменяемые начальные параметры — ActorId, FactionId, клетка появления, HP, бонус инициативы/атаки, защита и урон.
- `EncounterRules`: ОД за ход, цена атаки, допустимый перепад высоты.
- `Encounter`: создание очереди, проверка/исполнение команд, победа и приватное изменяемое состояние участников.
- `TacticalCommand`: Move, Attack, EndTurn с command ID и ActorId.
- `CommandResult`: принято/отказ, код причины, ревизия, признак повторной доставки, события результата.
- `EncounterSnapshot` / `ActorSnapshot`: данные только для чтения. `Definition.Position` остаётся исходной позицией; актуальная клетка — `ActorSnapshot.Position`.
- `IRandomSource` / `DeterministicRandom`: отдельный поток случайности столкновения, алгоритм `xorshift32-v1`, ненулевое uint-состояние.

## Правила прототипа

| Правило | Реализованное поведение | Статус решения |
|---|---|---|
| Инициатива | d20 + бонус; равенство — ActorId по ordinal-сравнению | Техническое правило D1 |
| Порядок исходных данных | Перед бросками участники сортируются по ActorId | Гарантия воспроизводимости |
| ОД | По умолчанию 3; передаются через EncounterRules | Пример GDD, настраиваемый прототип |
| Движение | Цена пройденных клеток, без цены стартовой клетки | GD-SYS-GRID-001 |
| Атака | По умолчанию 1 ОД; только соседняя клетка по стороне и допустимой высоте | Временная базовая атака |
| Попадание | d20 + AttackBonus >= Defense; без специальных правил natural 1/20 | Упрощение D1 |
| Урон | Фиксированный Damage из определения; HP не уходит ниже нуля | Упрощение D1 |
| Промах | Расходует цену атаки и один бросок | Техническое правило D1 |
| Завершение хода | Только EndTurn, доступен и при 0 ОД | Техническое правило D1 |
| Новый ход | Выбранному живому участнику выдаётся полный бюджет ОД | Реализовано |
| Новый раунд | После обхода очереди; мёртвые пропускаются | Реализовано |
| Победа | Осталась одна живая фракция; новые действия запрещены | Реализовано |

Встреча требует минимум две фракции, уникальные ID и разные проходимые стартовые клетки. Нейтральные отношения, ничья, спасброски от смерти и состояния раненых пока не моделируются.

## Контракт команды

1. Проверяется ID уже принятой команды.
2. Проверяется состояние столкновения, существование/жизнь и активный ход участника.
3. Проверяются назначение, путь/дальность и бюджет ОД.
4. Допустимое действие атомарно меняет состояние и увеличивает ревизию на 1.
5. Выдаётся список событий; представление обновляется по актуальному snapshot.

Отклонённая игровая команда не меняет HP, клетки, ОД, очередь, раунд, ревизию или RNG. Неправильная конфигурация/аргументы API являются ошибкой разработчика и приводят к исключению.

### Повторная доставка

- Повтор принятой команды с тем же ID и содержимым возвращает `IsReplay = true` и не исполняет действие повторно.
- Список событий такого ответа пустой, чтобы повтор не запускал VFX/анимацию второй раз.
- Тот же ID с другим содержимым отклоняется как `CommandIdConflict`.
- Кэш содержит принятые команды и живёт до уничтожения Encounter. После отказа новая попытка действия должна получать новый ID; отклонённые команды не записываются в журнал принятых.
- Replay содержит ревизию исходного результата; для текущего состояния нужно читать свежий snapshot.

Это защита внутри текущего процесса. Журнал между save/load, сетевая доставка и восстановление Encounter из snapshot пока не реализованы.

## Владение данными и случайностью

Encounter — единственный изменяющий состояние владелец. Определения и snapshots доступны только для чтения. Экземпляр RNG выделяется на одно столкновение; визуальные эффекты и другие системы не должны использовать этот экземпляр.

Состояние RNG доступно для будущего адаптера сохранения; из uint-состояния можно продолжить тот же поток. Snapshot D1 является диагностическим/представленческим объектом, а не JSON DTO кампании. Формат пользовательских слотов и пятиатрибутный профиль текущей игры не менялись.

## Проверки

Native Unity Test Runner: 24 новых тестовых метода в сумме для Encounter, сетки и RNG. Проверяются неправильный ход, бюджет, путь, повтор и конфликт ID, попадание/промах, победа, пропуск мёртвого, освобождение клетки, неизменность snapshot и независимость от порядка входных данных.

Play Mode полигон подтвердил расход ОД, ручное завершение хода, завершение боя, скрытие мёртвого и отсутствие изменений от idle-кадров. Подробности и ограничения — в отчёте D1.
