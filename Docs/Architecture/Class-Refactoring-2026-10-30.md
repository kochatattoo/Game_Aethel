## Изменения кода

До изменения `Encounter` одновременно создавал/хранил участников, назначал инициативу, управлял ходами, искал путь, выполнял атаку, определял победу и учитывал повторы команд. Теперь это композиция конкретных внутренних классов:

| Класс | Ответственность |
|---|---|
| `Encounter` | Публичная командная граница, общая валидация, replay/conflict, ревизия, чтение снимка |
| `EncounterRoster` | Валидация начального состава, живые занятые клетки, определение победы |
| `ActorState` | Runtime-состояние участника с private setters и явными операциями |
| `InitiativeOrder` | Назначение и сортировка инициативы, смена ходов, пропуск погибших и раунды |
| `MovementResolver` | Предпросмотр пути, проверка полной цены и применение движения |
| `MeleeAttackResolver` | Проверки ближней атаки, d20, списание ОД, урон и события |

Все пять collaborators — `internal`; изменяемые участники не выдаются внешнему коду. Не добавлены контейнер, event bus, registry обработчиков или интерфейсы для единственных реализаций. Зависимости передаются через конструкторы; оба места использования d20 получают один поток RNG от Encounter.

В самостоятельные файлы вынесены `GridCell`, `GridPath`, `ActorSnapshot`, `IRandomSource`, `CommandError`, `TacticalEvent` и `MotionMoveResult`. Namespace, видимость публичных типов и сигнатуры API сохранены. `TacticalEventKind` расположен рядом с событием, `TacticalCommandKind` — рядом с командой.

Существующие `.meta` сохранены. Для 12 новых `.cs` добавлены уникальные GUID в минимальном формате, уже используемом модулем; из-за недоступности Editor metadata подготовлена локальным инструментом. Импорт в Unity остаётся частью следующей проверки. Схема JSON, атрибуты профиля, сцены, prefab, ScriptableObject, asmdef, пакеты и ProjectSettings не изменены.

## Ограничения проверки

MCP проекта возвращал `Command expired after 60000ms in queue` при чтении сцены/Console/Play Mode. Повтор через установленный клиент моста дал тот же результат. Поэтому **новая компиляция в Unity Editor, Native Unity Test Runner, Play Mode и player-сборка этим этапом не подтверждены**. Доступные проверки доказывают компиляцию и поведение независимого C#-ядра вне Editor. Проверка импорта и затронутых полигонов в Unity остаётся необходимой перед интеграцией следующей фичи.

Когда мост снова отвечает: выполнить Assets/Refresh, дождаться компиляции, запустить EditMode с фильтром `PetProject.Tactics.Tests` (39 методов), затем регрессии и оба runtime-полигона через Tools/PetProject. Не требуется сохранять production-сцены или менять Build Settings.
